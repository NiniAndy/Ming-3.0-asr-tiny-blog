02 / 模型架构

语音感知，与语言理解相连接

Audio Encoder × Ling-tiny-v3

音频 → 文本

统一语音与文本输入

音频经过 Audio Encoder 与 MLP Projector，文本通过 Tokenizer，汇入语言模型完成转写。

混合注意力

3 : 1 混合注意力

采用 3 层 Kimi Delta Attention 与 1 层 Gated MLA 的组合，并结合 MoE 结构。

CONTEXT ASR

以提示补充识别上下文

使用相关热词或前序对话引导领域术语识别。长音频可分块编码，仍受模型上下文长度限制。

与仓库可执行脚本使用相同的核心调用。将 speech.wav 换成自己的音频文件。

03 · Python 示例
import soundfile as sf
import torch
from transformers import AutoModelForCausalLM, AutoProcessor
from examples.hf_runtime import decode_transcript, prepare_asr_request

checkpoint = "./Ming-3.0-asr-tiny-model"
processor = AutoProcessor.from_pretrained(checkpoint, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    checkpoint, trust_remote_code=True, dtype=torch.bfloat16,
    device_map="cuda:0", attn_implementation="sdpa",
).eval()

waveform, sample_rate = sf.read("speech.wav", dtype="float32", always_2d=True)
inputs = prepare_asr_request(processor, (waveform.T, sample_rate)).to(model.device)

with torch.inference_mode():
    eos = model.config.text_config.eos_token_id
    output = model.generate(
        **inputs, max_new_tokens=256, do_sample=False,
        eos_token_id=eos, pad_token_id=eos, no_repeat_ngram_size=10,
    )

print(decode_transcript(
    processor.tokenizer, output[0, inputs.input_ids.shape[1]:].tolist(),
))

普通转写和 Context ASR 默认使用同一种音频输入格式：cuda:0、BF16、SDPA、greedy decoding、10-gram 重复限制和最多 256 个新 token。Context ASR 仅在 <AUDIO> 前连续拼接主题、热词或上文，--device 和 --max-new-tokens 可按需调整。

使用说明

音频混音并重采样至 16 kHz，长音频按块编码，输入和输出总长度仍受上下文限制。输出为纯文本，不提供词级时间戳或说话人分离，不支持图像和视频输入；当前验证范围不包含量化、分布式生成与流式音频输入。
